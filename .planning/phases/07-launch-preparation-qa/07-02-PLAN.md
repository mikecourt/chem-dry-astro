<objective>
Ensure WCAG AA accessibility compliance and cross-browser compatibility.

Purpose: Accessibility is both a legal requirement (ADA) and SEO factor. Cross-browser testing ensures all users can access the site regardless of their browser choice.
Output: Accessibility score 95+, verified cross-browser functionality, documented compliance.
</objective>

<context>
@.planning/PROJECT.md
@.planning/ROADMAP.md
@07-01-SUMMARY.md (if exists)

**Accessibility targets:**
- WCAG AA compliance
- Color contrast ratio: 4.5:1 minimum for text
- All interactive elements keyboard accessible
- Proper heading hierarchy
- Alt text on all images
- Form labels properly associated

**Cross-browser matrix:**
Desktop: Chrome, Firefox, Safari, Edge
Mobile: iOS Safari, Chrome Mobile

**Critical flows to test:**
1. Navigation (header, footer, mobile menu)
2. Quote form submission
3. Phone link click-to-call
4. City page switching
</context>

<tasks>

<task type="auto">
  <name>Task 1: Automated accessibility audit</name>
  <action>
Run accessibility audit using browser tools:
1. Use Lighthouse accessibility audit on homepage
2. Check WAVE or axe DevTools results
3. Document all accessibility violations
4. Categorize by severity: Critical, Serious, Moderate, Minor
  </action>
  <success>Full accessibility audit documented with issues categorized</success>
</task>

<task type="auto">
  <name>Task 2: Color contrast validation</name>
  <files>src/styles/, tailwind.config.mjs</files>
  <action>
Verify color contrast ratios:
1. Check CTA buttons against backgrounds
2. Verify body text (#444444) against white/gray backgrounds
3. Check link colors for sufficient contrast
4. Verify error/success message colors
5. Document any failing contrast ratios
  </action>
  <success>All text meets 4.5:1 contrast minimum</success>
</task>

<task type="auto">
  <name>Task 3: Keyboard navigation testing</name>
  <action>
Test full keyboard navigation:
1. Tab through homepage - verify logical order
2. Test all interactive elements are focusable
3. Verify focus indicators are visible
4. Test form submission with keyboard only
5. Test mobile menu with keyboard
  </action>
  <success>All interactive elements keyboard accessible with visible focus</success>
</task>

<task type="auto">
  <name>Task 4: Fix accessibility issues</name>
  <action>
Address identified accessibility issues:
1. Add missing alt text to images
2. Fix heading hierarchy issues
3. Ensure form labels are properly associated
4. Add ARIA labels where needed
5. Improve focus indicators if needed
  </action>
  <success>All Critical and Serious accessibility issues resolved</success>
</task>

<task type="auto">
  <name>Task 5: Cross-browser testing</name>
  <action>
Test critical flows in each browser:
1. Desktop Chrome - full functionality test
2. Desktop Firefox - verify layout and forms
3. Desktop Safari - verify layout (if available)
4. Mobile Chrome - responsive layout, tap targets
5. Mobile Safari - responsive layout, click-to-call

For each browser, verify:
- Navigation works (desktop hover, mobile hamburger)
- Forms submit correctly
- Phone links work
- Images load properly
- No layout breaking issues
  </action>
  <success>All critical flows work in all target browsers</success>
</task>

<task type="auto">
  <name>Task 6: Responsive breakpoints verification</name>
  <action>
Test responsive design at key breakpoints:
1. Mobile: 375px (iPhone SE)
2. Mobile Large: 414px (iPhone Plus)
3. Tablet: 768px (iPad)
4. Desktop Small: 1024px
5. Desktop: 1280px
6. Desktop Large: 1536px

Check each breakpoint for:
- Text readability
- Proper spacing
- No horizontal scroll
- Images scale correctly
- CTA buttons appropriate size
  </action>
  <success>Layout works correctly at all breakpoints</success>
</task>

</tasks>
